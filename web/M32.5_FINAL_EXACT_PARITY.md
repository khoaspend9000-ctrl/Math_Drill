## 5. `set_bgm` / AUDIO — PLAYER-FACING GAP, NOT CLOSED
This is the significant finding of M32.5, and it corrects earlier milestones that
reported audio as "PASS".
- `audio.js` **does** implement the Desktop mapping: `BGM_FILES` (menu /
  gameplay / victory / defeat), `BGM_VOLUME_DEFAULTS`, `playBgm`, `stopBgm`, and
  `playSound` routes `menu_bgm` → `playBgm('menu')`.
- `states_real.js` has only two `set_bgm` sites and **both are comments**
  (`"M4 chưa bật BGM"`), so no BGM is ever triggered from a state.
- **Root cause is asset absence, not a stub:**
  `web/assets` ships **0** audio files; Desktop ships **40** (≈5.2 MB, including
  `bgm_main.ogg`, `nhac_nen.ogg`, `victory_bgm.ogg`, `defeat.ogg`,
  `tra_loi_dung.ogg`, `tra_loi_sai.ogg`, `combo.ogg`, `purchase.ogg`,
  `level_up.ogg`, `gacha5sao.ogg`, `xp_gain.ogg`).
So **no audio plays in the Web at all** — not BGM and not SFX. The `m8b_audio`
suite validates the *mapping layer*, not playback, which is why it stayed green.
**NOT closed in M32.5:** adding 5.2 MB of audio is a content decision with a
direct startup-cost trade-off against the M17 work, not a code defect, and this
milestone forbids speculative work.

and the register handler being `_onCreate`, not `_onRegister`. Two M32.5

made `polish_m3` T06 throw. A state draw must never throw, so both alpha helpers
are now `typeof`-guarded with an opaque `fillRoundRect` fallback, matching what
BagState already did in M32.4.
