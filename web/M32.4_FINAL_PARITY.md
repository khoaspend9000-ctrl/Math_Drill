**A real pre-existing bug found and fixed.** `global.Game.itemFx` was only ever
**read** (`states_real.js:1049`, `:4211`) and never constructed, so
`ItemEffectSystem` was never instantiated in the browser: the bag always rendered
**empty** and the use-item/buff mechanic was unreachable. `_fx()` now builds the
same lazy singleton Desktop has at module level, reusing the existing module and
live auth. Before the fix the browser showed `cards: 0`; after, `cards: 3`.

**Renderer constraint handled.** `Renderer` exposes no `line()`/`fillRect()`.
The background grid, divider and the 5★ rainbow border are drawn through
`R.ctx` with `typeof` guards, so the state also draws under the test stub `ctx`.

## 10. Is 100% player-facing Desktop parity met?
**Not claimed.** The 26-state inventory is closed with no PARTIAL/MISMATCH/
MISSING/UNKNOWN, and every player-facing screen was re-read from source. But the
AchievementView card **border colours** and **text offsets** still differ from
`main.py:1977-2000` (Web uses gold 3px / white 2px and shifted text positions), and
the three P3 items above are unaddressed. Those are cosmetic or admin-only, but
they are real differences, so parity is **near-complete, not certified**.

## 11. Remaining UNKNOWN
None at the state level. Exact question-text parity between Desktop and Web
remains unprovable because Python seeds Mersenne Twister and the Web uses
`Math.random` (`mt19937.js` is not wired); no source or test requires
seed-for-seed equality, so this is recorded as a platform difference, not a defect.
