## Input — main.py:2038-2075
1. If feedback is active, **only a mouse click** dismisses it and advances
   (2040-2045). Nothing else is processed.
2. Otherwise, `MOUSEBUTTONDOWN` and `not book.is_flipping`:
   - `back_btn` → `MenuState()` (2047)
   - `speak_btn` → TTS (2048-2050)
   - answer button, first match wins, `break` (2051-2075)

## Answer — main.py:2052-2074
`is_correct = str(v) == str(self.ans)` (2053); `answer_times` appended (2054);
correct → `self.sc += 10` (2057); wrong → `snd_wrong.play()` (2059);
`adaptive_ai.record_answer(...)` (2063); skill-mastery update (2064-2071);
`FeedbackOverlay(...)` (2073); `pending_advance = True` (2074).

## Timer — **THERE IS NONE**
`update()` (2076-2082) contains no countdown and no timeout branch. The
"timed quiz" description in the M32.2 brief is **incorrect**; source wins.
`avg_time` is *measured* per question (2028) but never enforced.

## Update — main.py:2076-2082
`book.update(dt)`; `feedback.update(dt)`; if `feedback.dismissed and
pending_advance` → clear the flag and `_advance_question()`.

## Draw — main.py:2083-2099
`fill((165,214,167))` → `book.draw` → blackboard `(80,120,520,480)` with a
brown frame r15 at −10 inset and `(20,50,20)` r10 board → "THỬ THÁCH" y180 and

"Câu" → `f"Điểm: {sc}  |  Độ khó: {label}"` y300 → question in

## Score / Progress / Completion — main.py:2021-2037
`cc += 1`; at `cc >= tc`: `correct_answers = sc // 10`,
`accuracy = (correct_answers / tc) * 100`.

## Pass / Fail — main.py:2031
`if accuracy >= 60:` → pass. With `tc = 10` this means **6 correct**.

## Victory transition — main.py:2032-2034
`add_xp(correct_answers * 20)` then
`VictoryState("HOÀN THÀNH THỬ THÁCH!", self.sc, "Thử Thách", stats)`.

## Defeat transition — main.py:2035-2036
`DefeatState("CỐ LÊN NÀO! LÀM LẠI NHÉ 💪", correct_answers, self.tc, "Thử Thách", stats)`.

## Retry
Not a DailyState concern. `DefeatState` retry reaches back here via
`main.py:1029` — this is exactly the branch M32.1 ported and which was
**unreachable until this milestone**.

## Persistence
`add_xp(...)` on pass only (2032-2033). No daily-completion marker, no streak,
no claim, no `account_system.save()` inside DailyState.

## Audio/effects
`snd_wrong.play()` on a wrong answer (2059). Correct feedback is handled by
`update_combo` / `FeedbackOverlay`.

## Cleanup / Re-entry
No timers or listeners. Desktop constructs a fresh `DailyState()` per visit
(680), so every `enter()` value is re-applied.

# Existing Web DailyState

## Current purpose before M32.2
A **daily-reward claim screen** ("ĐIỂM DANH HÀNG NGÀY") built on
`DailyRewardSystem` — XP/gold claim, 7-day streak, `claimedToday`.

## Source mismatch
Desktop has **no such screen**. Desktop's daily reward is a **Menu popup**:
`main.py:475-476` `reward_info = claim_daily_reward(); self.daily_popup =
DailyRewardPopup(reward_info)`, updated at `502-503` and drawn at `746-747`.
Because the Web had no popup layer it promoted that claim UI to a full screen
named `DailyState` — colliding with Desktop's quiz of the same name.

# Desktop vs Web decision

The claim screen is **retained but renamed**, not deleted:

| | Before | After |
|---|---|---|
| Desktop quiz `main.py:2002` | missing | `DailyState` (`daily`) |
| Daily reward popup `main.py:475` | `DailyState` (wrong name) | `DailyRewardState` (`daily_reward`) |

Rationale: deleting a working reward feature would remove player-visible
functionality Desktop *does* have (just as a popup). Renaming removes the name
collision and keeps the behaviour reachable. It is documented as a **Web
adaptation**: the Web has no popup system, so the popup is a screen. Two
`polish_m3` tests (T05, T12) that asserted the reward grid were retargeted to
`DailyRewardState` — retargeted and renamed, not deleted or weakened.
