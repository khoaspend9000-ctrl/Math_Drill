# Existing Web DailyState

## Current purpose before M32.2
A **daily-reward claim screen** ("ĐIỂM DANH HÀNG NGÀY") built on
`DailyRewardSystem` — XP/gold claim, 7-day streak, `claimedToday`.

## Source mismatch
Desktop has **no such screen**. Desktop's daily reward is a **Menu popup**:
`main.py:475-476` `reward_info = claim_daily_reward(); self.daily_popup =
DailyRewardPopup(reward_info)`, updated at `502-503` and drawn at `746-747`.
Because the Web had no popup layer it promoted that claim UI to a full screen
named `DailyState` — colliding with Desktop's quiz of the same name.

# Desktop vs Web decision

The claim screen is **retained but renamed**, not deleted:

| | Before | After |
|---|---|---|
| Desktop quiz `main.py:2002` | missing | `DailyState` (`daily`) |
| Daily reward popup `main.py:475` | `DailyState` (wrong name) | `DailyRewardState` (`daily_reward`) |

Rationale: deleting a working reward feature would remove player-visible
functionality Desktop *does* have (just as a popup). Renaming removes the name
collision and keeps the behaviour reachable. It is documented as a **Web
adaptation**: the Web has no popup system, so the popup is a screen. Two
`polish_m3` tests (T05, T12) that asserted the reward grid were retargeted to
`DailyRewardState` — retargeted and renamed, not deleted or weakened.

# Question Differential

## Method
Executed Desktop `question_generator.QuestionGenerator.generate_question(grade=3, rid, 3, None)`
in Python and the Web `QuestionGenerator.generate_question(...)` in Node, over the same
rid set `[1, 5, 17, 40, 41, 60]`.

## Deterministic status — **NOT deterministic, and not claimed to be**
Python seeds `random` (Mersenne Twister); the Web generator uses `Math.random`. The repo
contains `web/js/mt19937.js` but it is **not wired into the question generator**. Therefore
question *text and numeric values cannot be compared field-by-field*, and this document
does not claim they match.

## Fields actually compared
| Field | Result |
|---|---|
| `rid` acceptance across the Daily range (1–40 / 1–60) | both accept all six |
| option count | 4 in both |
| correct answer present in the option list | true in both, all six |
| template family per rid | same family (rid 1 place-value, rid 5 measurement, rid 17 area) |

## Observed difference (not a defect)
```
Desktop rid=1  -> "900 + 30 + 9"
Web     rid=1  -> "900 + 30 + 5"
```
Same template, different random draw. Expected given the RNG difference.

## Limitations
- Exact text/value parity is **unverified** and would require wiring `mt19937.js` into the
  generator *and* matching Python's `random.seed` consumption order.
- `DESKTOP BUG — PARITY PRESERVED` / `PARITY MISMATCH` cannot be adjudicated at the
  value level for the same reason.
- The M15-A M15-question-variety suite already proved 0/342 lessons produce a repeated
  question, so the structural contract the Daily quiz depends on is independently green.
